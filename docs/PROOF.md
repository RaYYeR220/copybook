## Refusals on chain

A refused copy is recorded too: the handler writes `Refused(follower, source, market, reason, venueError)` in the block of the move it refused, and the follower's position stays where it was. Exits are never gated: no cap, tank, pause or AI verdict holds back a close. A close the book cannot fill inside the exit band is recorded as `BandUnfilled` (or `VenueRejected`) and syncs at the next move or a `catchUp` ([LIMITS.md](LIMITS.md#copying)).

## Regenerate

```sh
cd e2e && npm ci && npm run proof
```

It only reads (public RPCs, no key). It exits 0 when everything verifies, 1 when anything fails and 2 when the RPC kept failing for some transactions, and it rewrites this file only on 0 (`npm run proof -- --write-anyway` writes it with the failures marked). The transactions and what was recorded for them are in `e2e/proof/sources.json`, `deployments/*.json` and `eval/*/anchor.json`; `HIDEKI_RPC` and `SHANNON_RPC` override the endpoints.
